# v1.2 Dogfood — Known Issues / Bug List

Issues surfaced while dogfooding the v1.2 streaming-partials build. Tagged
here for later triage; not blocking v1.2 ship.

## Trailing-silence hallucinations — RESOLVED (VAD trim)

**Status (v1.2).** Fixed via `TrailingSilenceTrimmer`: the drained buffer is
run through the already-vendored Silero VAD offline to find the last speech
frame, and trailing silence/noise past a 300 ms hangover is dropped before the
final `whisper_full` pass (`PipelineCoordinator.processSamples`). Conservative
guards: no trim when no speech is found or the trailing silence is under
400 ms, so genuine quiet trailing words survive. Original analysis kept below
for context.

**Symptom.** If the user stops speaking but doesn't release the hotkey
immediately, the final transcript gains a spurious trailing word — most
commonly "okay" or "my date" (mis-hearings of room tone / breath /
keyboard noise).

**Likely cause.** Whisper is being handed audio that ends in
N seconds of near-silence + background noise. The decoder
has a known tendency to produce filler tokens ("okay", "thanks for
watching", language-model artifacts) when the acoustic signal weakens
but doesn't cleanly end. With `large-v3-turbo` the artifact set leans
toward short conversational fillers.

**Fix candidates (to evaluate later, not now):**

- **Trim trailing silence before the final `whisper_full` pass.** Run the
  recorded buffer through a VAD (Silero is already vendored — see
  `Vendor/silero-vad/` and the unused `silero_vad.onnx` resource) and
  drop any trailing frames whose voice probability falls below a
  threshold for ≥ 300 ms. This shortens what whisper sees and removes
  the conditions that produce filler tokens.
- **Boost `no_speech_thold`** in `WhisperTranscriptionService` for the
  final pass so segments dominated by silence are dropped rather than
  emitted. Risk: legitimate quiet trailing words get suppressed.
- **Post-filter known hallucination tokens** when they appear as the
  *only* word in the last segment and the segment's average log-prob is
  below threshold. Conservative; matches whisper.cpp's own
  `--suppress-non-speech-tokens` heuristic but applied at the segment
  level.

**Adjacent observation.** This is independent of the streaming
partials work — the same hallucinations existed pre-v1.2 and surface in
the final transcribe pass, not the streaming passes.
