# Manual test — Settings window (v1.1)

Confirms the menu-bar Settings UI works end-to-end across General / Presets / Vocabulary / About panes.

## How to open

- Menu bar → SayMoore → **Settings…** (Cmd-,)

## T1 — General pane

1. Toggle **Mute audio chimes** ON. Save state via UserDefaults `audio.feedback.muted`.
2. Quit + relaunch SayMoore.
3. Dictate. **Expect:** no Glass/Pop chimes on record/stop.

Limitation: chime state is read at AppDelegate launch; toggle takes effect on next relaunch. (Live toggling deferred to v1.1.1 polish.)

## T2 — Presets pane

Three buttons:

- **Open presets.json** — opens Finder selecting `~/Library/Application Support/SayMoore/presets.json`. Same behavior as the existing "Edit Presets…" menu item.
- **Reload Presets** — triggers an immediate reload (same path as the FSEvents watcher). Use after manually editing the JSON.
- **Check for Updates…** — runs `presets.upgradeStatus()`. Shows "up to date" alert or the three-button upgrade dialog (Merge / Overwrite / Keep Mine).

## T3 — Vocabulary pane

Table view with two columns (Phonetic, Canonical), inline editing, add/remove buttons, Save button.

1. **Add a row:** click "Add row". A blank row appears. Type `Quinn` / `Qwen`. Click Save.
2. **Verify on disk:** `cat ~/Library/Application\ Support/SayMoore/presets.json | jq .vocabulary` — the new entry is present.
3. **Verify in app:** dictate "Quinn handles the cleanup". The post-substitution rewrites to "Qwen".
4. **Remove a row:** click a row to select it, click "Remove selected". Save. Verify on disk.

## T4 — Bounds enforcement

1. Add 51 rows. Click Save.
2. **Expect:** red error caption: "Too many vocabulary entries (max 50)." The on-disk file is NOT modified — the prior valid state stays.
3. Remove one row. The red error CLEARS automatically (the fix from the adversarial review).
4. Save. Now the 50-entry vocabulary lands on disk.

Other bounds errors trigger similar inline messages:
- Per-side entry > 64 bytes
- Total billed bytes > 512

## T5 — Focus + selection survive a Save

1. Open Settings → Vocabulary. Click into one of the canonical fields. Type a few characters.
2. Click Save.
3. **Expect:** the field you were editing keeps its content; the table doesn't visibly remount. (The fix in this slice preserves row UUIDs and stops `refresh()` after Save, which was previously rotating IDs and stealing focus.)

## T6 — Hand-edit while Settings is open

1. Open Settings → Vocabulary.
2. In another window (e.g. BBEdit), open `~/Library/Application Support/SayMoore/presets.json` and add a new vocab entry. Save.
3. Switch back to the Settings window.
4. **Expect:** the new entry appears in the table (FSEvents watcher fires → AppDelegate.reloadPresetsAndNotifyOnFailure → SettingsWindow.notifyExternalReload → VM refresh). Existing entries keep their UUIDs.

## T7 — About pane

Shows version + build (e.g. "Version 1.0.1 (build 3)"), brief description, "View on GitHub" link. Click the link → opens https://github.com/seemoretmoore/saymoore in the default browser.

## T8 — Re-open the window

1. Open Settings, edit vocab WITHOUT saving, close the window.
2. Open Settings again from the menu.
3. **Expect:** the in-progress unsaved edits are still there. The window is the same instance, retained by AppDelegate.

If you want a clean slate, click **Reload Presets** in the Presets pane — that re-pulls from disk and overwrites the in-memory editing state.

## Adversarial-review fixes verified by automated tests

The Sonnet adversarial review surfaced these P1s, all fixed and covered by `SettingsViewModelTests`:

- `@StateObject` → `@ObservedObject` (VM is externally owned by SettingsWindow)
- `refresh()` preserves row UUIDs by matching `(phonetic, canonical)`
- `commitVocabulary` no longer calls `refresh()` — in-memory state is authoritative post-save
- `lastError` clears on `addVocabRow` / `removeVocabRow` so stale errors don't linger while users fix the input
- FSEvents reload → VM refresh wired through `SettingsWindow.notifyExternalReload`
