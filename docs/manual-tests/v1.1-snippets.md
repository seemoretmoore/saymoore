# Manual test — voice snippets (v1.1)

Confirms `insert <name>` expansion before the cleanup LLM sees the transcript.

## Schema

`~/Library/Application Support/SayMoore/presets.json`:

```json
{
  "default": "...",
  "snippets": {
    "sig": "— Tracy",
    "email": "tracy@clinicalpattern.com"
  }
}
```

Trigger pattern: `insert <name>` (case-insensitive on the name, word-boundary anchored). Name must match `[A-Za-z0-9_-]+`.

## T1 — Bundled snippets work out of the box

The bundled `presets.example.json` ships `sig` and `email` snippets. Fresh installs get them; existing users keep their existing snippets (or none) on Merge.

1. In Notes, Ctrl-Ctrl, dictate *"thanks insert sig"*, Ctrl-Ctrl.
2. **Expect:** "Thanks — Tracy." (or similar; the LLM may add punctuation around the snippet but the expansion must be present).

## T2 — Snippet expands BEFORE cleanup LLM

Dictate *"hey insert email please send the report"* in Notes.

**Expect:** the LLM sees the expanded text and can adjust grammar around it. Final paste: "Hey, tracy@clinicalpattern.com, please send the report." (capitalization may vary).

## T3 — Case-insensitive name match

Dictate *"INSERT SIG"* in all caps.

**Expect:** expansion still fires (`insert` and the name both match case-insensitively).

## T4 — Word-boundary protection

Dictate *"the insertsig string"* with no space between `insert` and `sig`.

**Expect:** no expansion. The word-boundary anchor blocks substring matches.

## T5 — Missing `insert` keyword

Dictate *"the sig should be at the end"*.

**Expect:** no expansion — bare `sig` without the `insert` prefix does not trigger.

## T6 — Bounds enforcement

Edit `presets.json` and add a snippet with a space in the name (e.g. `"two words": "x"`). Save.

**Expect:** banner: "A snippet name in presets.json contains invalid characters (only letters, digits, _, -) — snippets disabled." Other presets keep working.

Other bounds (each silently disables snippets and posts a banner):
- 21+ snippets → "Too many snippets (max 20)"
- Name > 32 bytes or value > 512 bytes → "A snippet entry is too long"
- Total billed bytes > 8 KB → "Snippets are too large overall (max 8 KB)"
- Array-shaped value (`"snippets": ["bad"]`) → "Snippets are malformed"

## T7 — Hot-reload

Edit `presets.json`, add or change a snippet, save. Without restarting SayMoore, dictate again.

**Expect:** the new snippet is live (FSEvents triggers reload). Confirmed by the existing `PresetWatcher` path that already handles vocabulary edits.

## T8 — Command Mode doesn't expand snippets

Dictate "send the report by Friday." → pastes. Within 5s, Ctrl-Ctrl, say *"insert sig"*, Ctrl-Ctrl.

**Expect:** Command Mode treats "insert sig" as a literal voice edit instruction (telling the LLM to add a signature). The snippet does NOT expand here — Command Mode branches before `maybeCleanup` and uses `CommandService` with its own prompt.

## T9 — Bundled-preset upgrade preserves user snippets

1. Add a custom snippet to your `presets.json`.
2. Force an upgrade by setting `"$schemaVersion": 0` in the file. Restart.
3. Choose **Merge** in the upgrade alert.
4. **Expect:** your custom snippet is intact. The bundled `default` template is adopted.

If you choose **Overwrite** instead, your custom snippets are lost — only the bundled samples remain. This is the documented behaviour.

## Notes

- The expansion runs BEFORE the cleanup LLM, so it works on fast-path (≤3-word) transcripts too — short dictations that skip cleanup still get snippets.
- Snippets do NOT apply on the Command Mode path. If you want a "signed off" instruction, say *"add my signature"* and let the rewrite LLM compose it.
- Future polish: a Settings UI pane for managing snippets without hand-editing JSON. Tracked under the v1.1 Settings window task.
