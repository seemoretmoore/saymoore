# Manual test — Command Mode (v1.1)

Verifies the second-Ctrl-Ctrl-within-5s rewrite flow against real apps.

## Mechanism recap

1. Dictate normally → SayMoore pastes the cleaned text.
2. Within 5 seconds, without switching apps or clicking elsewhere, press Ctrl-Ctrl again.
3. Speak the edit instruction (e.g. "make it more formal", "shorter", "add a question mark").
4. Press Ctrl-Ctrl to stop.
5. SayMoore posts Cmd-Z (undoing the prior paste) and pastes the rewritten text in its place.

Window timing is `PipelineCoordinator.commandModeWindow` (5.0 s default). Eligibility requires the frontmost bundle ID to match the bundle that received the prior paste.

## T1 — Happy path in Notes

1. Open Notes, click into a note.
2. Ctrl-Ctrl. Say: *"Send the report by Friday."* Ctrl-Ctrl to stop.
3. **Expect:** "Send the report by Friday." pasted.
4. Within 5s, Ctrl-Ctrl. Say: *"Make it more formal."* Ctrl-Ctrl.
5. **Expect:** the original sentence is undone and replaced with a more formal rewrite (e.g. "Please ensure the report is delivered by Friday.").

## T2 — Chained rewrites

1. Run T1 to completion.
2. Within 5s of the *rewrite*, Ctrl-Ctrl again, say *"Add a polite ending."*, Ctrl-Ctrl.
3. **Expect:** the formal rewrite is undone and replaced with another rewrite that includes a polite sign-off.
4. The window resets on every successful rewrite-paste, so chains can continue indefinitely as long as each follow-up is within 5s.

## T3 — Window expiry

1. Dictate any normal sentence in Notes. Wait 7 seconds.
2. Ctrl-Ctrl, say *"make it shorter"*, Ctrl-Ctrl.
3. **Expect:** SayMoore treats this as a fresh dictation — pastes "Make it shorter." into Notes, does NOT rewrite anything.

## T4 — Cross-app PTT

1. Dictate in Notes. Immediately switch focus to Messages (Cmd-Tab).
2. Within 5s, Ctrl-Ctrl, say *"shorter"*, Ctrl-Ctrl.
3. **Expect:** Messages receives "Shorter." as a fresh dictation. Notes' prior paste is untouched.

## T5 — Rewrite failure (no destructive change)

Force a placeholder response by editing `CommandService.placeholderResponses` to include the test string and rebuilding (or by dictating something that prompts the LLM to say "done").

1. Dictate a normal sentence.
2. Within 5s, trigger Command Mode with a no-op instruction (e.g. *"do nothing"*).
3. **Expect:** if the LLM returns "done" or another placeholder, SayMoore posts a "Command Mode failed — original text is unchanged" banner. NO Cmd-Z is sent. The original paste remains.

## T6 — Esc during Command Mode recording

1. Dictate normally.
2. Ctrl-Ctrl to start Command Mode recording. Press **Esc** before stopping.
3. **Expect:** recording discarded, no Cmd-Z, no banner. Prior paste intact.

## T7 — BBEdit / code-adjacent context

Command Mode uses a generic editor prompt (not the per-app cleanup preset). Verify it still does the right thing in BBEdit:

1. In BBEdit, dictate: *"add a function called getUserById"* → pastes as-is (or close to it).
2. Within 5s, Ctrl-Ctrl, say *"make it asynchronous"*, Ctrl-Ctrl.
3. **Expect:** rewrite reflects async-ification, e.g. "add an async function called getUserById" or similar. The BBEdit cleanup preset is NOT applied — Command Mode uses its own prompt. (This is intentional: editing is a different shape than first-pass cleanup.)

## T8 — Apps where Cmd-Z doesn't undo the paste

Some apps treat a paste as multiple undo units, or don't undo paste at all (Terminal, some web app text fields). When Command Mode hits one of these:

1. Dictate into Terminal.app.
2. Within 5s, trigger Command Mode.
3. **Expect:** Cmd-Z does whatever Terminal's Cmd-Z does (probably nothing or unrelated). The rewritten text gets pasted after the original. **Documented limitation** — not all apps support paste-as-one-undo-unit.

## T9 — Focus moved before rewrite-paste

1. Dictate in Notes.
2. Ctrl-Ctrl to start Command Mode. While recording, click into a different app's text field.
3. **Expect:** SayMoore detects the focus change on the rewrite-paste step and aborts. The prior paste in Notes is untouched. Banner: "Focus changed — recording discarded".

## Notes

- Command Mode uses a separate Ollama prompt (`CommandService.buildPrompt`) with two ZWJ-fenced blocks (`<original>` + `<instruction>`). It does NOT honour per-app cleanup presets.
- Failure modes that fall through to a normal paste of the transcript: empty rewrite, placeholder rewrite, length-collapse (cleaned < 20% of original). The user sees a banner; the prior text stays put.
- The `commandModeWindow` is currently a compile-time default (5s). A future polish iteration may surface this in Settings.
