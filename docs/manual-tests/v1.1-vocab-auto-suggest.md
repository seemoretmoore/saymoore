# Manual test — vocabulary auto-suggest (v1.1)

Confirms SayMoore proactively spots proper-noun-like patterns the user hasn't added to vocabulary and offers a one-time-per-session reminder.

## Mechanism

After every successful paste, `PipelineCoordinator` fires `onPasteSucceeded` with the cleaned text. `AppDelegate.considerVocabSuggestion` runs the text through `VocabSuggester.consider`, which:

1. Extracts proper-noun-like terms via three regex patterns:
   - PascalCase / mixed camelCase (`FooBar`, `AVAudioEngine`)
   - SCREAMING_SNAKE_CASE with at least one underscore (`API_KEY`)
   - ALL CAPS ≥4 letters (`GRAPHQL`)
2. Filters out anything already in vocabulary (either column, lowercase).
3. Filters out terms already suggested this session (in-memory Set, reset on app launch).
4. Returns the first qualifying term, or `nil`.

If non-nil → low-priority notification: `Add to vocabulary? "{TERM}" looks like a proper noun...`

## T1 — Dictate a brand-new proper noun

1. Open Notes, dictate "let's pin to use Postgres for the new service".
2. **Expect:** paste lands. Then a banner: `Add to vocabulary? "Postgres" looks like a proper noun. Edit presets.json under "vocabulary" to capture it on future dictations.`

Single-cap words like "Postgres" actually do NOT match — the patterns require at least one internal uppercase or 4+ all-caps. So Postgres won't trigger. Try `GraphQL` or `FooBar` instead.

Adjusted T1:

1. Dictate "deploy GraphQL to staging".
2. **Expect:** banner with suggestion for "GraphQL".

## T2 — Dedupes within a session

1. Dictate "GraphQL is up" (banner fires for GraphQL).
2. Dictate "GraphQL is still up" 30 seconds later.
3. **Expect:** no second banner. Per-session dedupe Set prevents re-firing for the same term until the next app launch.

## T3 — Already-in-vocabulary terms stay quiet

1. Confirm `vocabulary` in your `presets.json` includes an entry for `Qwen` (the bundled set does).
2. Dictate "let's tune Qwen for shorter outputs".
3. **Expect:** no suggestion banner. The phonetic OR canonical match (lowercase) blocks the candidate.

## T4 — Mixed candidates: first new one wins

If two new terms appear in one dictation, only the first one (by appearance order in the regex sweep) is offered. The second waits for the next dictation that mentions it (or is offered as the first new one in a later session).

1. Dictate "use GraphQL with FooBar today" (assuming neither is in vocab).
2. **Expect:** banner for GraphQL (PascalCase pattern fires first).
3. Dictate again "GraphQL and FooBar working".
4. **Expect:** banner for FooBar (GraphQL is already in the suggested Set).

## T5 — Common acronyms skipped

Dictate "in the USA the TV is OK".

**Expect:** no banner. 2- and 3-letter ALL CAPS are skipped by design to keep noise down.

Also: ordinary sentence-start capitalized words ("Alex", "Notes", "Hello") are NOT matched. Only multi-cap or ALL-CAPS-≥4 patterns trigger.

## T6 — Surface only after a successful paste

1. Trigger a known-fail path (e.g. mic blocked, no audio captured, focus changed mid-paste).
2. **Expect:** no auto-suggest banner. The hook fires only on `try await paste.paste(...)` success.

## T7 — Command Mode skips auto-suggest

Command Mode pastes its rewritten text through `replacePriorPaste`, not `paste`. The auto-suggest hook is wired only to the dictation paste path.

1. Dictate "send the report", paste lands, banner fires if a new proper noun appears.
2. Within 5s, trigger Command Mode, say "add GraphQL to the list", rewrite pastes.
3. **Expect:** no auto-suggest banner from the Command Mode rewrite (intentional — too noisy on rapid follow-ups).

## Notes

- The suggested Set is in-memory only; relaunching SayMoore resets it. A persisted "I've dismissed this" set is on the v1.2 roadmap.
- The notification body tells the user to edit JSON manually. Once the Settings UI ships (next task in the v1.1 plan), the banner will gain a one-click "Add" action that opens the Vocabulary pane pre-filled.
- Patterns are tuned conservatively to minimize false positives; users will likely want some they don't get (single-cap names like "Alex", "Postgres"). Surface in feedback if so — adding a 4th pattern is a one-line change.
