# Manual test — bundled-preset auto-upgrade (v1.1)

Confirms the schema-version detection + three strategies behave correctly for the v1.0.1 → v1.1 transition (every existing user has no `$schemaVersion` field on disk).

## Setup

Path: `~/Library/Application Support/SayMoore/presets.json`

Back up the live file before each scenario:
```bash
cp ~/Library/Application\ Support/SayMoore/presets.json /tmp/presets.bak.json
```

## T1 — Fresh install (no prompt)

1. `rm ~/Library/Application\ Support/SayMoore/presets.json`
2. Launch SayMoore.
3. **Expect:** no upgrade prompt. File materialized with `"$schemaVersion": 1`.

```bash
grep schemaVersion ~/Library/Application\ Support/SayMoore/presets.json
# "$schemaVersion": 1,
```

## T2 — Existing v1.0.1 user, Merge (default path)

1. Edit `presets.json`: remove the `$schemaVersion` line. Add a custom override:
   ```json
   "overrides": { "com.example.test": "MY CUSTOM PROMPT {{transcript}}", ... }
   ```
2. Launch SayMoore.
3. **Expect:** NSAlert "Updated cleanup prompts available". Click **Merge**.
4. **Verify:**
   - `presets.json` now has `"$schemaVersion": 1`.
   - `"default"` template matches the bundled baseline (verbose, with discourse-marker + no-placeholder rules).
   - `"overrides"."com.example.test"` is still `"MY CUSTOM PROMPT {{transcript}}"` — preserved.
   - Existing vocabulary entries are preserved.
   - Notification posts: "Default prompt updated. Your overrides and vocabulary were preserved."

## T3 — Existing user, Overwrite

1. Set up as T2.
2. Launch → NSAlert → click **Overwrite**.
3. **Verify:**
   - `"overrides"."com.example.test"` is GONE.
   - File now mirrors bundled `presets.example.json` exactly (4 standard overrides only).
   - Notification: "Presets replaced with bundled defaults."

## T4 — Existing user, Keep Mine

1. Set up as T2.
2. Launch → NSAlert → click **Keep Mine**.
3. **Verify:**
   - `"$schemaVersion": 1` added to file.
   - `"default"` is unchanged from the user's version.
   - `"overrides"."com.example.test"` is unchanged.
   - Relaunching does NOT show the prompt again.

## T5 — "Check for Preset Updates…" menu item

1. After any T2-T4, click the SayMoore menu bar icon → **Check for Preset Updates…**
2. **Expect:** alert "Presets are up to date" (since version was bumped in T2-T4).
3. To re-trigger: edit `presets.json` and manually set `"$schemaVersion": 0`. Click the menu item.
4. **Expect:** the three-button upgrade alert re-appears.

## T6 — Disk version ahead of bundled (no downgrade)

1. Edit `presets.json` and set `"$schemaVersion": 999`.
2. Launch SayMoore.
3. **Expect:** no upgrade prompt (SayMoore never downgrades user state).

## T7 — Hot-reload after upgrade

1. After applying Merge (T2), with SayMoore still running, immediately dictate into Notes.
2. **Expect:** the new default prompt is live without a relaunch. The PresetWatcher FSEvents path fires on the upgrade write, and `applyUpgrade()` also calls `reloadPresetsAndNotifyOnFailure` inline.

## Notes
