# Manual test — Whisper `initial_prompt` biasing (v1.1)

Confirms acoustic recognition is biased toward `vocabulary` canonicals BEFORE the deterministic post-substitution path runs.

## Mechanism

`PresetStore.biasHint(from:)` joins the unique canonical forms of every vocabulary entry into a comma-separated string. `PipelineCoordinator.processSamples` passes that hint as `initial_prompt` to whisper at every recording. The existing `applyVocabSubstitutions` regex still runs after cleanup as a safety net for cases where the bias doesn't catch the word.

## T1 — Cold-start acoustic accuracy on proper nouns

This is the headline benefit: words that Whisper used to get wrong on the first attempt should now transcribe correctly without needing the post-substitution.

1. Verify `~/Library/Application Support/SayMoore/presets.json` has the bundled vocabulary entries (FSEventStream, AVAudioEngine, Qwen, SwiftUI, etc.).
2. Dictate in Notes: *"the Qwen model handles SwiftUI views and FSEventStream callbacks"*.
3. **Expect:** all four proper nouns transcribe correctly. Even with no post-substitution rule (e.g. delete the "Quinn"→"Qwen" entry temporarily), the bias should encourage Whisper to pick "Qwen" over "Quinn" / "Coen" / "Gwen".

Compare with biasing disabled (temporarily empty the `vocabulary` array): "Quinn / Sweet UI / FS event stream" misses are more common.

## T2 — Empty vocabulary → no bias

1. Edit `presets.json` so `vocabulary` is empty (`"vocabulary": []`) and save.
2. Dictate normally.
3. **Expect:** SayMoore works exactly as before — no `initial_prompt` set on whisper, no console log line for the bias.

In the debug log you should see `[transcribe] initial_prompt set (N bytes)` lines ONLY when vocab is non-empty.

## T3 — Dedup of multi-phonetic → single canonical

Two phonetics in the bundled vocabulary map to "Qwen" (`Quinn` and `Clem`). The bias hint should list "Qwen" once, not twice.

This is verified by `testBiasHintDeduplicatesCanonicals`. Manually: if you add 10 phonetic entries that all point to one canonical, the hint stays compact.

## T4 — Hot-reload changes the bias

1. Add a new vocab entry: `{"phonetic": "Wirepicker", "canonical": "WireTester"}` and save.
2. Without restarting, dictate.
3. **Expect:** the next dictation's bias hint includes "WireTester". (Confirm via the debug log entry showing the byte count went up.)

## T5 — Bias does NOT bypass cleanup or vocab substitution

The bias is acoustic only — it doesn't change downstream behavior:

1. The cleanup LLM still gets the post-biased raw transcript.
2. `applyVocabSubstitutions` still runs after cleanup as a safety net.
3. Snippet expansion still happens before cleanup.

Verified by the existing pipeline-integration tests covering cleanup, fast-path, fallback-to-raw, and snippet expansion all continuing to work alongside the new bias hint.

## Notes

- Bias hint is currently GLOBAL (joined across all vocab entries). Per-app scoping (Slack-only vs BBEdit-only canonicals) is deferred to v1.2 alongside per-app vocabulary.
- whisper.cpp's `initial_prompt` is most effective at the start of audio and degrades over long recordings. SayMoore caps recordings at 90s so this is rarely a concern.
- The hint is bounded by the existing 512-byte vocabulary cap, well within whisper's token budget.
